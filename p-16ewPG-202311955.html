# 『忍たま乱太郎GB えあわせチャレンジパズル』完全解析まとめ（Ver.4）


## 1. RAM メモリマップ（確定・検証済み）

  • `0xC478`: ゲームモード判定（`1` = 通常モード）
  • `0xC47B`: 表裏モード判定（`0` = 表ステージ、`1` = 裏ステージ）
  • `0xC481`: メインループのステート管理
  • `0xC486`〜`0xC488`: 現在の総獲得スコア（24bitリトルエンディアン、画面表示の下2桁「00」を除いた数値）
  • `0xC489`〜`0xC48C`: 周回・踏破判定用の一時変数（前回踏んだマス、今回踏んだマス、カウント、回転方向）
  • `0xC48D`: 現在のステージ内での獲得スコア（下2桁の飾りゼロを除いた1バイト値、最大25,500点）
  • `0xC490`: 汎用カウンタ（アクション回数・ルート歩数などステージ関数ごとに使用）
  • `0xC491`: その場から動かずにハンマーを空振りした連続回数
  • `0xC492`: 上下左右の外壁叩きビットフラグ（1回目: 1,2,4,8 / 2回目: 16,32,64,128）
  • `0xC493`: キューブ（お邪魔箱）を消した累計数
  • `0xC494`: 特定条件の累積達成回数カウンタ（裏13面、表21面などで使用）
  • `0xC49A`: アイテム出現判定の監視終了（クローズ）フラグ（`0`=監視中、`1`=終了 ※成功時だけでなくNG行動・時間切れ等の失敗時も`1`になる）
  • `0xC49B`: ★アイテム（秘密の巻物）状態（`0`=未達、`1`=出現条件成立、`2`=出現中、`3`=取得済み）
  • `0xC890`〜`0xC8C0`: 7×7フィールド盤面配列（49バイト：`0`=床、`1`=壁、`2〜10`=絵キューブ9種、`11`=白箱、`12`=黒箱、`13`=硬い白箱、`14`=硬い黒箱）
  • 四隅のインデックス：`0`(左上), `6`(右上), `42`(左下), `48`(右下) / 中央：`24`（`0x18` / アドレス `0xC8A8`）
  • `0xC8C1`〜`0xC8F1`: 7×7フィールド地形・床属性マップ（49バイト）
  • `0`=普通の床、`1`=ゾーンフィールド（3×3＝9マスの絵合わせ完成エリア）、`2`（・`3`）=白黒キューブ出現予告マーキング、`7`=アイスバーン（滑る床）、`9`=ブロック（侵入不可）
  • `0xC8F2`: 現在のステージ番号（`0x01`〜`0x20` = 1〜32面）
  • `0xC947`, `0xC949`: ステージ環境・ギミック設定フラグ（4面周期ローテーション等）
  • `0xCD59`: ステージ残り時間（秒）
  • `0xCD5F`〜`0xCD60`: 16ビット汎用フレームタイマー（60fps換算、共通関数 `FUN_2b63` で使用）
  • `0xCD6C`: プレイヤー向き・装備状態
  • 上位4bit（向き）：`0x10`(16)=上, `0x20`(32)=下, `0x40`(64)=左, `0x80`(128)=右
  • 下位4bit（特殊アイテム所持）：`1`(Bit0)=すーぱーはんまー, `2`(Bit1)=しのびがたな, `4`(Bit2)=消費型時計/すーぱーしゅりけん, `8`(Bit3)=すーぱーこて（ミスまたは使用で喪失）
  • `0xCD6D`: プレイヤー現在位置（7×7マス番号 `0〜48`、`0x18`=中央）
  • `0xCD6E`: プレイヤーアクション状態（`0`=待機, `1`=移動, `2`=押す, `3`=ハンマー, `4`=引く, `0x0B`=壁を押す）
  • `0xCD7E`, `0xCD7F`, `0xCD80`, `0xCD85`: 道中で入手する特殊アイテム（鍵・強化防具）所持フラグ（ミスすると喪失）
  • `0xCDF5`: 最後に「引く」アクションで動かした対象
  • `0`=空振り, `1`=絵キューブ, `2`=白箱, `4`=黒箱, `8`=硬い白箱, `16`=硬い黒箱, `128`=お邪魔キャラ
  • `0xCE04`, `0xCE14`: ステージ内お邪魔キャラ（最大2体）の現在マス番号（`0〜48`）
  • `0xCE0E`, `0xCE1E`: ステージ内お邪魔キャラの行動ステータス（`0`=通常／接触リセット後、`2`=プレイヤー発見・追跡状態）
  • `0xCE3B`: 1回の連鎖消去で変化した固キューブ個数リスト（`-1`=`0xFF`終端、`rom2::7a87` 経由で `0xCF33` へコピー）
  • `0xCECB`: 消費型アイテム（表16面・裏15面）の状態フラグ
  • `0xCED6`: 2回目以降プレイ時の得点アイテム出現フラグ（`C49B == 3` かつ条件達成時に `1`）
  • `0xCF1F`: 盤面のキューブ蓄積・危険度カウンタ（`7`以上でピンチBGM切替）
  • `0xCF32`〜`0xCF41`: 関数間で使い回される一時作業用メモリ（スクラッチパッド）
  • キューブ連鎖消去イベント時：`CF33` = 最大波及ステップ数（一番遠いキューブまでの距離＋1）、`CF34` = 消去されたキューブの合計個数
  • `0xCFCA`: 現在のステージ基本BGM番号（1〜28面=`4`、29〜32面=`10`）
  • `0xCFCB`: ピンチBGM（`0x06`）再生中フラグ（`0`=通常BGM、`1`=ピンチBGM再生中）
  • `0xCFD7`: 特殊装備パスワード入力結果（`0`=なし、`1`=`1414`[すーぱーこて]、`2`=`1732`[すーぱーしゅりけん]、`3`=`2236`[すーぱーはんまー]、`4`=`8823`[しのびがたな]）
  • `0xD900`〜`0xD913`: パスワード入力バッファ（最大20バイト、未使用部は `0x7F` パディング）
  • `0xD920`〜`0xD927`: コンティニューパスワード復号・チェックサム計算用ワーク
  • `0xD92C`: パスワード入力カーソル位置（`0x00`〜`0x0D`）
  • `0xD92D`: 入力文字パレットのカーソル位置（`0x00`〜`0x17`）
  • `0xFFF3` (HRAM): サウンド再生リクエストキュー（メインループ内の `FUN_04c3` が監視し `RST 0x18` へ渡す）

## 2. システム構造・装備＆サウンド・テキスト仕様

  • **条件判定呼び出し機構**: アクション・イベント発生時に `RST 0x20`（`E7`）経由で `rom3::401b`〜`40e4` のディスパッチテーブルを呼ぶ。裏条件は `rom3` 内関数、表条件は `rom3::7ad1`〜`7b1c`（`E7 08 XX C9`）を経由して `rom8::4000`〜 のテーブルへ飛ぶ。
  • **ステージ条件検索Hex**: `fa f2 c8 fe XX`（`XX` はステージ番号 `01`〜`20`）
  • **共通計算関数**: `FUN_rom3__7a52` / `FUN_rom8__7375` は32ビット除算の余り（`mod`）を `CF3A` に返す。
  • **最終面（32面）＆防具システム**:
  • 道中で入手する特殊アイテムは、お邪魔キャラへの接触に耐える防具（猶予）の役割を持つと同時に、32面の秘密の巻物出現条件の前提（鍵）になっている。
  • 途中でミス（残機喪失）や消費型アイテムの使用を行うと該当フラグが失われるため、後半ステージから32面まではノーミスかつ防具・アイテムを温存したまま突破する必要がある。
  • **サウンド制御構造**:
  • `RST 0x18`（`DF` → `rom0::0018` → `FUN_0061`）がサウンドドライバの共通入口（`A` レジスタにサウンドIDを指定、`0xFF` で全停止）。
  • ステージ開始時は `rom2::40f5` でステージ番号に応じて `0xCFCA` に `4`（1〜28面）または `10`（29〜32面）をセットし再生する。サウンドテスト23番目の曲は本編未使用トラックの可能性が高い。
  • **独自文字コード体系**:
  • パスワード用英字（0始まり）: `A=0x00` 〜 `Z=0x19`
  • メッセージ表示用英大文字（`0xE0`始まり）: `A=0xE0` 〜 `Z=0xF9`、`0x7F`=スペース
  • スタッフロール文字列（`AKADEMY`, `STAFF` 等）はROM内に非収録。

## 6. 独自文字コード体系＆テキスト解析まとめ（確定済み）

### A. 文字コード割り当て表（1文字＝1バイト方式）

  • **数字（メッセージ・解説文用）**: `0x80`=`0`, `0x81`=`1`, `0x82`=`2` ... `0x89`=`9`（※パスワード入力画面では `0x00`〜`0x09`）
  • **英大文字（2系統）**:
  • パスワード用（0始まり）: `0x00`=`A`, `0x01`=`B`, `0x02`=`C` ... `0x19`=`Z`
  • メッセージ表示用（`0xE0`始まり）: `0xE0`=`A`, `0xE1`=`B`, `0xE2`=`C` ... `0xF9`=`Z`
  • **ひらがな（`0xC0`始まり・清音ベース1バイト）**:
  • あ行: `0xC0`=あ, `0xC1`=い, `0xC2`=う, `0xC3`=え, `0xC4`=お（※一部テキストでは `0xC1` 始まりシフトあり）
  • か行: `0xC5`=か, `0xC6`=き, `0xC7`=く, `0xC8`=け, `0xC9`=こ
  • さ行: `0xCA`=さ, `0xCB`=し, `0xCC`=す, `0xCD`=せ, `0xCE`=そ
  • た行: `0xCF`=た, `0xD0`=ち, `0xD1`=つ, `0xD2`=て, `0xD3`=と
  • な行: `0xD4`=な, `0xD5`=に, `0xD6`=ぬ, `0xD7`=ね, `0xD8`=の
  • は行: `0xD9`=は, `0xDA`=ひ, `0xDB`=ふ, `0xDC`=へ, `0xDD`=ほ
  • ま行: `0xDE`=ま, `0xDF`=み, `0xE0`=む, `0xE1`=め, `0xE2`=も
  • や行: `0xE3`=や, `0xE4`=ゆ, `0xE5`=よ
  • ら行: `0xE6`=ら, `0xE7`=り, `0xE8`=る, `0xE9`=れ, `0xEA`=ろ
  • わ・を・ん: `0xEB`=わ, `0xEC`=を, `0xED`=ん
  • **修飾・制御コード**:
  • `0xF0`: 濁点（直前の清音文字に後置。例：`0xD2 0xF0` = で）
  • `0xF1`: 半濁点（直前の清音文字に後置）
  • `0xF8`: 長音記号（ー）
  • `0x7F` / `0xFF`: スペース・段落区切り
  • `0x01`: 改行
  • `0x00`: 文字列終端（NULL）

### B. スタッフロール有無の検証結果

  • 英字テーブル（`AKADEMY`, `YUMENOSUKE`, `STAFF`）および確定ひらがなテーブル（`df e3 e4 e1 d8 cc c8`＝みやゆめのすけ / `e4 e1 d8 cc c8`＝ゆめのすけ）の双方で全ROM Hex検索を実施した結果、該当文字列は**0件（完全に非収録）**と確定。
  • テキストデータ（`rom6::58f4`〜`5c48` 等）はプリントシールの解説文や画面UIのみに使用されており、スタッフクレジットは最初から実装されていない。
